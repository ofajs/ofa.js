# benchmark 方法学踩坑手册

以下每条都是本仓库实测踩过的坑，动基准代码或解读数字前先过一遍。

## 1. 先后采集顺序 = 系统性热偏差

**症状**：A/B 两个版本分两次采集（先旧后新），结论随运行次序翻转；同一场景
一次显示新版 -22%、换一天又 +8%。

**根因**：机器热漂移（负载/降频）随时间单调变化，后采集的一方永远承受更差的
机器状态——这不是噪声，是系统性偏差。

**正确姿势**：交替采集——同一轮内 A/B 紧挨着各跑一遍，多轮取中位数；机器漂移
对同轮内双方对称生效。stanz 的 run.mjs（`packages/stanz/benchmark/`）是参考实现。

## 2. 预热不足 → JIT 未分层，数字虚高

**症状**：首轮特别慢；某场景"稳定地慢"但换结构测就快。

**根因**：Proxy 陷阱链、递归冒泡这类代码要上千次迭代才完成 V8 分层编译。
只预热 1 次调用，前几轮都在跑解释器/未优化代码，中位数被污染。

**正确姿势**：预热完整一轮（或至少 2000 次迭代）再开始计时。
亚毫秒级样本低于计时分辨率时不要给百分比结论，直接判"相当"
（见根 AGENTS.md 的分辨率规则）。

## 3. 长页面生命周期污染后续场景

**症状**：同一页面按序跑多个场景，靠后的场景测出"稳定回退"；但把该场景单独
放到干净页面、或跑完后同页复测，回退消失甚至反转。

**根因**：页面存活越久，V8 优化状态与 GC 堆越"脏"，且对不同模块图的影响
不对称。曾把新版 stanz 冒泡误判为 -22%，独立 A/B 实测 +103%。

**正确姿势**：**每个场景独立页面**（stanz 的 bench.html 支持 `?only=id`），
页面生命周期从几分钟缩到几秒；页内仍然 A/B 交替。宁多开页，不信长页面。

## 4. 同页共存的前提：零全局副作用

两个版本的实现要放进同一页面交替测量，前提是**互不争夺全局**：stanz 不写
window、不注册元素，可以同页 A/B；drill 占 `window.lm` 且注册 `l-m`/
`load-module` 标签，两版同页必冲突，只能分页对比（用交替轮次抵消偏差）。
给新包做基准前，先确认它有没有全局副作用。

## 5. 算法结论要用独立环境交叉验证

**症状**：浏览器基准显示回退，但代码审不出原因。

**正确姿势**：换 node（纯逻辑库可直接跑）或写一个最小化页面内 A/B 复现脚本，
独立验证。stanz 冒泡的 -22% 就是靠 node A/B（2 倍快）与页面内复测推翻的。
**"数字稳定"不等于"结论正确"——系统性偏差同样很稳定。**

## 6. 基建杂项

- **playwright webServer 就绪探测**：`url` 必须指向一个真实存在且返回 2xx 的
  文件；指向没有 index.html 的目录根会一直 404，表现为"webServer 启动超时"
  （配置见根 `playwright.config.mjs`）。
- **npm workspaces cwd 陷阱**：在包目录里跑 `npm run xxx`，npm 会就近命中该包
  自己的同名脚本。包内脚本要跨目录时显式写
  `--config=../../playwright.config.mjs`；日常统一从仓库根执行。
- **浏览器二进制版本必须与 @playwright/test 匹配**：报
  "Executable doesn't exist" 就 `npx playwright install <browser>`
  （下载慢可设 `https_proxy`）。之前强杀过的安装会留下 `__dirlock`，
  按提示删除即可。
- **基准夹具不进仓库**：批量生成的重复文件由 run.mjs 动态生成、`finally`
  删除，`.gitignore` 加条目兜底（drill 的 fixtures 即此模式）。
- **终端表格 CJK 对齐**：中文按 2 列计宽，用 `padW`（见 stanz run.mjs 的
  `charWidth`），否则表格歪掉。
- **页面脚本崩溃要快速失败**：采集循环里挂 `page.on("pageerror")` 直接抛错，
  别干等 waitForFunction 超时（曾因 bench 预热行的 undefined 崩溃白等 3 分钟）。
